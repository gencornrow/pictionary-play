Dual-backend mode: cloud database on Lovable, local Postgres in Docker

## Goal

One codebase, two hosting options, chosen by an environment variable:

- **Lovable preview/published** keeps using the built-in cloud backend exactly as today.
- **Self-hosted Docker** runs fully offline with a Postgres container — no cloud account, nothing leaves your network.

## How it works

```text
                 Browser (identical for both modes)
                    |  calls server functions
                    v
        Data-access layer (new, server-side)
          switch on DATA_BACKEND env var
          |                          |
   "cloud" (default)           "local" (docker-compose)
   cloud database              Postgres container
   realtime push               ~1s polling
```

## Changes

### 1. Server-side data-access layer

- New `src/lib/backend/` module exposing the operations the game needs: create/join room, list players/teams, add strokes, post chat messages, cast votes, advance phases, read scores.
- Two implementations behind one interface:
  - **cloud**: uses the existing cloud backend connection (current behavior preserved).
  - **local**: connects to Postgres with the `postgres` npm package using `DATABASE_URL`.

### 2. Rewire the UI to call server functions

- `src/routes/index.tsx` (create/join room) and `src/routes/game.$code.tsx` (all game reads/writes) switch from direct browser database calls to the new server functions.
- Browser code becomes backend-agnostic; the switch is invisible to players.

### 3. Live updates

- Cloud mode: keep the existing realtime subscriptions.
- Local mode: poll the server every ~1 second for strokes/chat/phase changes (lightweight, fine for 30 players).

### 4. Local Postgres in Docker

- Add a `postgres:16` service to `docker-compose.yml` with a named volume.
- Add a `db/init.sql` script (generated from the existing migrations) that creates all tables automatically on first container start.
- App container gets `DATA_BACKEND=local` and `DATABASE_URL=postgres://...` wired to the Postgres service; add a healthcheck so the app waits for the database.

### 5. Docs

- Update `README.md`: how the switch works, how to run fully local (`docker compose up`), and what stays on the cloud backend for the Lovable-hosted version.

## What does NOT change

- No auth is added or removed — the game has no sign-in today and stays that way.
- Game rules, screens, colors, and player experience are identical in both modes.
- The Lovable-hosted version behaves exactly as it does now.

## Technical notes

- Local mode intentionally drops realtime push for polling; strokes and chat may lag by up to ~1 second on self-hosted only.
- Security rules (RLS) apply to cloud mode; the local Postgres sits behind the app's server functions instead, which perform the same input validation.
- Both backends share the same table structure, so future changes must update both the migrations and `db/init.sql` — a documented checklist item in the README.
